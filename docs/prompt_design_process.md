# プロンプト作成プロセスおよび決定根拠

本ドキュメントは、本実験で使用されたシステムプロンプトの設計プロセス、構成要素、およびその決定根拠を詳細にまとめたものです。
実験の再現性を担保するため、実際のコードベース（`src/lib/constants.ts`, `src/app/api/chat/route.ts`, `services/cloneai/clone_agentAI.py`）に含まれる実装履歴とロジックに基づいています。

## 1. 作成プロセス概要

プロンプトの作成は、以下の3段階のフェーズを経て最適化されました。

1.  **Phase 1: 定量的・定性的ペルソナの定義 (Structured Definition)**
    - 客観的な属性データ（年齢、居住地）と、心理学的指標（Big5）を構造化データとして定義。
2.  **Phase 2: プロトタイプによる挙動検証 (Behavioral Testing)**
    - Pythonスクリプト(`clone_agentAI.py`)を用いた初期テスト。
    - LLM特有の「丁寧すぎる」「長すぎる」バイアスを検知。
3.  **Phase 3: 制約条件の強化と動的注入 (Constraint Tuning)**
    - 「短文主義」「説明拒否」などの具体的制約をシステムプロンプトに追加。
    - RAG検索結果に基づく動的なコンテキスト注入の実装。

## 2. プロンプト構成要素と決定根拠

現在のプロンプトは、大きく分けて **A. 静的ペルソナ定義** と **B. 動的行動指針** の2パートで構成されています。

### A. 静的ペルソナ定義（Static Persona）
`src/lib/constants.ts` に定義されているベース部分です。

| 構成要素 | 具体的内容・パラメータ | 決定根拠 (Rationale) |
| :--- | :--- | :--- |
| **基本属性** | 名前、年齢(21)、職業(大学生)、居住地など | 被験者本人の事実情報。ハルシネーション（架空の設定の捏造）を防ぎ、一貫性を保つための基盤。 |
| **心理指標 (Big5)** | 外向性:57, 神経質:29, 開放性:68, 協調性:48, 誠実性:34 | **科学的再現性の確保**。抽象的な「明るい性格」等の記述ではなく、心理学的な数値指標を用いることで、モデルの性格調整を定量的に行う意図。 |
| **価値観・嗜好** | 「好奇心が全て」「損得合理」「夜型」など | 個人の意思決定プロセスを模倣するため。特に「損得合理」という指針は、冷淡とも取れる短文応答の正当性をモデルに理解させるために重要。 |
| **固有名詞** | 好きなYouTuber（板橋ハウス等）、尊敬する人 | 具体的な固有名詞を含めることで、特定の文脈における語彙選択や話題の親和性を高めるため。 |

### B. 動的行動指針（Dynamic Behavioral Instructions）
`src/app/api/chat/route.ts` にて、リクエスト毎に動的に付与される追加指示です。初期テストで判明した課題（LLMの過剰な丁寧さ）を補正するために追加されました。

#### 1. 短文制約の強化
> **指示内容**: `出力は基本10文字以下に抑えること。 10文字前後を超えると違和感を感じる。`

- **課題**: 通常のLLM（Gemma等）はRLHF（強化学習）により「丁寧で網羅的な回答」をするよう調整されており、チャットボットとしては不自然に長くなる傾向があった。
- **根拠**: 実際のLINEログ分析の結果、本人の平均発話長が極めて短いことが判明したため、文字数制限を明示的な「違和感の基準」として提示。

#### 2. 説明・質問の禁止（Anti-Helpfulness）
> **指示内容**: `理由説明をしない` `質問を返さない` `話題を広げない` `感想で終わらせる`

- **課題**: ユーザーの質問に対し、LLMは「〜ですね。あなたは？」と質問を返したり、聞かれていない背景知識を解説する傾向がある。
- **根拠**: 本人のコミュニケーションスタイル（INTP的・自己完結型）を再現するため、LLMの「有用なアシスタント」としての振る舞いを強制的に抑制する必要があった。

#### 3. 思想・哲学的背景の注入
> **指示内容**: `実存主義的人生観` `資本主義批判` `友達なんて愚痴言い合うだけの他人`

- **根拠**: 表面的な口調（関西弁など）だけでなく、回答の内容（Content）に一貫性を持たせるため、根底にある判断基準を明文化して注入。

## 3. RAGコンテキストの注入ロジック

外部知識（RAG）を利用する場合、以下の形式でプロンプトに挿入されます。

```text
----------------
[Fact] 2024/01/01: バイトに行ってきた
[Thought] 生成AIの進化について考えていた
----------------
```

- **決定根拠**:
    - **カテゴリタグ付与**: `[Fact]` `[Thought]` を明記することで、モデルが「事実」と「意見」を区別して参照できるように設計。
    - **時系列情報の欠落防止**: コンテキスト自体には日時情報が含まれない場合でも、内容は「最近の記憶」として扱うよう暗黙的に設計（検索時に類似度と共に新しさも考慮される可能性があるが、現状の実装では純粋なベクトル類似度）。

## 4. 限界と改善点（Discussion）

- **Zero-shotの限界**: 現在はFew-shot（会話例の提示）を行わず、指示（Instruction）のみで制御しているため、稀に敬語が混ざる不安定さが残る。
- **コンテキスト長の制約**: 検索件数を3件に絞っているが、文脈によっては情報不足となる可能性がある。
